# SPEC: складской учёт инструмента и снаряжения (AlpGroup)

Статусы пунктов: `[ ]` не начато, `[~]` в работе, `[x]` сделано, `[?]` не решено.

## 1. Цель

Учёт инструмента и снаряжения: что на балансе, что на складе, что и на какой объект выдано, кто взял и когда вернул. Стек: Django + DRF; позже фронтенд и Telegram-бот.

Вне рамок на этом этапе: каталог проектов с фото, видео, данными заказчика и описанием работ.

## 2. Сущности

### 2.1 Категория (самосвязанная: у категории может быть родитель)
Верхний уровень: Электроинструмент, Снаряжение, Мелкий ручной.
- [?] Подкатегории: добавляются через админку по мере необходимости.

### 2.2 Инструмент / снаряга
- [ ] название
- [ ] категория
- [ ] количество
- [ ] примечание
- [ ] фото: главное и возможность добавить несколько
- [ ] статус: на складе / выдан / утерян / списан
- [ ] дата постановки на баланс, дата снятия с баланса

Кто и когда взял или сдал хранится не в полях инструмента, а в журнале движений (см. 2.3).

### 2.3 Движение (журнал операций)
- [ ] инструмент, количество
- [ ] тип: постановка на баланс / выдан / принят / утерян / списан
- [ ] кто взял: сотрудник или бригада
- [ ] объект, на который выдан
- [ ] дата и время операции
- [ ] кто внёс запись
- [ ] признак отмены (отменённая запись остаётся в журнале)

Из этой таблицы строятся все выборки и отчёты.

### 2.4 Сотрудник
- [ ] ФИО
- [?] остальные поля (телефон, роль, Telegram ID, бригада, активен или уволен)

### 2.5 Бригада
- [ ] название
- [?] остальные поля (бригадир, состав, вид работ)

### 2.6 Объект (минимальный справочник)
Нужен только для выдачи («выдано на объект») и выборок по виду работ.
- [ ] название или адрес
- [ ] вид работ (справочник: мойка, гидра, монтаж и т.д.)
